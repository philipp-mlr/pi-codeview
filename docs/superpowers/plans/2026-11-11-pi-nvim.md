# pi.nvim Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Turn pi-codeview into pi.nvim: Philipp's everyday pi plugin for Neovim (ask with context and diagnostics, see the agent work, annotate and send), with review as an opt-in checkpoint mode, all keys under `<leader>p`, the activity log removed.

**Architecture:** Same two components and socket protocol as today. The log goes first (less to rename), then one mechanical rename across both sides (they share socket paths, protocol version and mode names, so they must change together to keep the e2e suite green), then the new features on top.

**Tech Stack:** TypeScript (vitest, fake pi), Lua (Neovim 0.12, headless specs + e2e driving real nvim against the extension), Nix for Philipp's config.

**Spec:** `docs/superpowers/specs/2026-11-11-pi-nvim-design.md`

## Global Constraints

- Every identifier in the spec's "Name and identifiers" table is renamed exactly as listed; no `codeview`/`Codeview` remains in code, tests, keys, commands, namespaces, buffer names or highlight groups (docs/superpowers history files excepted).
- Migration reads old, writes new: `pi-nvim.checkpoints` unset → fall back to `pi-codeview.mode` (`review`/`on` → true); switching always writes `pi-nvim.checkpoints` explicitly (`true`/`false`) and never touches the old key; restore from last `pi-nvim-state`, else last `pi-codeview-state`; pruning covers `refs/pi-nvim/` and `refs/pi-codeview/`.
- `Mode = "checkpoints" | "off"`; `set_mode` accepts `checkpoints`/`on`/`review` and `off`/`vibe`; `PROTOCOL_VERSION = 2` on both sides.
- Keys exactly: `pa` ask, `pc` cancel, `ps` session, `pn` annotate, `px` remove annotation, `pr` send annotations, `pv` chunk panel, `pm` checkpoint mode — all `<leader>p…`; default keys never replace an existing mapping.
- Behaviour of checkpoint mode is unchanged (all existing review tests keep passing after renaming).
- Messages for sending annotations exactly as in the spec ("Sending annotations says what it sends").
- Diagnostics: ERROR and WARN only, max 20, errors first then by line, message collapsed and cut at 200 chars, rendered exactly as in the spec.
- Commits: conventional, signed; never `git add -f` under `.superpowers`.

## Review Focus

1. Upgrade path on Philipp's machine: a repo with `pi-codeview.mode=review` (bc-apps has `on`) comes up in checkpoint mode; a pi session saved with `pi-codeview-state` restores its open chunk and drafts.
2. Annotations visible on long lines with `nowrap` and on lines that also carry live marks, gitsigns and diagnostics signs.
3. `:PiCancel` while idle (no-op with a clear message) and while a checkpoint is waiting (chunk stays open; later send resumes).
4. Diagnostics from a buffer whose LSP isn't attached (none → no section) and from a selection inside one line.
5. Statusline never errors before setup / when not attached, after the rename.
